## 关键化用差异（与 lark-link 原版对比）

| 点 | lark-link | 本机 0.2.0 |
| --- | --- | --- |
| 图片下载 | 自写 REST `im/v1/messages/:id/resources/:key` | SDK 原生 `channel.downloadResource`，零适配代码 |
| 文件工具参数 | path + 必填 kind + caption | 仅 path，按扩展名自动分流图片/文件 |
| 安全 | 只限 workspaceRoot | realpath 白名单（工作区+数据目录，防符号链接穿越）+ 扩展名白名单 + 20MB 上限 |
| 文本提取 | 150KB 有界全文 | 150KB 界 + 8000 字符截断 |
| 会话反查 | session id 前缀 `lark-link:` 剥离 | exec.agent.id → chat 映射反查（含 web 会话覆盖项） |
| 卡片回调 | 独立模块 | 按本机 questions/approval 既有模式并入 commands.ts（`cmd\|` 前缀路由互不干扰） |
| read-only 档 | 直接调 permission.apply | 宿主无预设 → 双路径：先试预设、失败走 sandbox/mode + approval/policy 会话事件 |
| 诊断包发送 | 手写 im/v1/files + message.create | SDK `channel.send({file})` 原生映射（file_type:'stream'） |
| 持久化 | 无此问题 | 防 index.ts persist() 陈旧视图覆盖：savePermissionTier 独占写路径 |

## 遗留与说明

- /mode 多 preset 维持不吸（依赖 DSH preset 快照重建机制，收益不确定）。
- 未吸：probe 主动健康探测、断连补偿、环境代理规避（连接自愈细节，价值低于已吸项）。
- 实机验证缺口：媒体下载/工具发送/诊断包/卡片交互需真实飞书凭据端到端验证（当前为 mock 全覆盖）。
- 只读档若部署侧后续配置了 read-only 预设，代码自动优先走预设（已留 try 路径）。
- 诊断包不收集子代理日志与宿主配置文件（按范围）；/doctor 需要 im:resource 等下载权限时以实际报错为准。

## 结论

P2 五项全部落地：消除「媒体静默丢弃」短板、模型可回传文件、一条命令产出诊断包、/model 与 /permission 卡片化+持久化。0.1.0 的 9 项 + 0.2.0 的 5 项合计 **14 个吸收点**，lark-link 能力清单（17 项基准）中除有意丢弃项外已全部对齐或超越。
